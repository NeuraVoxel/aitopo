# Agent Note: DSH demo group with event topology sample

Status: implemented

## Problem

The demo's only DeepSeek Harness entry was a reserved, unrenderable business placeholder (`dsh-event-topo` in the `business` group); there was no home for DSH-related topology showcases.

## Decision

- `DemoSampleGroupId` gains `dsh`; the nav renders a "DeepSeek Harness" group between Agents and Business.
- The reserved placeholder is promoted to a real sample `demo/samples/dsh/event-topo.ts` (`id: 'dsh-event-topo'`, no longer `reserved`), modeling the DSH turn flow from the harness `docs/architecture.md`: `dsh CLI` → `Cordis Context` with `lifecycle` compose/mount edges into the four core plugins (agent-loop, llm adapter, tool registry, session log), and `event` edges back (`agent/request`, `llm/stream`, `tool/call`, `session/event`). Six nodes, nine edges, builtin icons only.
- `demo/samples/dsh/boot.ts` (`id: 'dsh-boot'`) migrates into the group from the agents directory: a recording generated by the harness `scripts/observe-boot.ts` of a real `dsh web` profile boot — five phase nodes chained by `flow` edges, with `network:compose` (patch layers in application order) and `network:mount` (plugin activation time axis) as double-click sub-networks. Keep generated output as-is; regenerate by re-running the script rather than hand-editing.
- `businessPlaceholders` becomes an empty list; the Business group renders only when it has rows.

## Alternatives considered

**Keep the placeholder and add a separate dsh sample.** Rejected: two rows for the same concept invites drift; the placeholder's promised id is reused as the real sample.

**Model the full bundle/profile composition tree instead of the turn flow.** Deferred: the event topology is the sample the placeholder promised; profile/bundle composition is a better fit for a follow-up sample once needed.

## Consequences

The `dsh` group is the home for future DSH showcases under `demo/samples/dsh/`. The registry test now asserts the four-group ordering and that the Business group is currently empty; re-adding business rows updates that assertion deliberately.

## Testing

`tests/demo-registry.spec.ts` gains "registers the DSH event topology in its own group", now pinning the dsh group's sample order (`['dsh-boot', 'dsh-event-topo']`), the boot document's phase count and both sub-networks, plus the event topology's mount targets and edge-kind counts; the ordering test pins getting-started < elements < agents < dsh with Business empty. Typecheck clean; the pre-existing `labelPosition` failure in the same file is unrelated and untouched.
